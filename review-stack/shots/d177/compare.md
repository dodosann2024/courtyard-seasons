## 六、骆驼喝水探针：是测试的问题，不是行为的问题

结论：**测试问题**。骆驼喝水的行为本身没问题，没改；吃草/喝水的判定也没改。

- 原来 d172 的探针：只要 drink 动画的 `getEffectiveWeight()` 大于 0.9 就记录嘴的位置，嘴抬起 3 厘米或者 60 秒到了就停，保留当时记录的结果。
  - 它不检查动画是不是真的在播（停掉的动画仍然报告最后的权重 1）；
  - 不检查 `camelGo` 有没有找到路；
  - 不检查有没有低头到底；
  - 也不重置会话状态（时间、天气、风、镜头控制、`a.tries`）。
  所以只要会话把低头过程打断，它就会留下半路的采样，并把特写镜头对准那里。
- 复现：权重在第 157 帧超过 0.9，这时嘴在水面以上 1.075 米；第 173 帧是 0.844 米，大约低头半秒后经过 0.83 米。把旧探针截在第 158 / 165 / 172 / 173 帧，分别得到 1.075 / 0.997 / 0.877 / 0.844，和报告里的 0.83 米、镜头不对一致。
- 新探针（`tools/e2e/d177-drink.mjs`）是确定性的：
  1. 先把场景设成固定状态（晴天、风 0.35、关镜头控制、另一只骆驼卧在休息点、重置重试和动画状态）；
  2. 要求 `camelGo` 成功；
  3. 只在 drink 真的在播且权重 > 0.9 时采样，取固定 4 秒窗口里嘴的最低点；
  4. 失败时给出原因（找不到路、没喝、中途被打断、重新规划），不返回半路的结果；
  5. 检查镜头偏移 < 5 厘米。

| 运行（`drink.json`） | 结果 | 嘴离水面 |
| --- | --- | --- |
| 新开 3 次 | 3/3 通过 | −0.033 米 |
| 紧接着再来一次（上一次的动画权重还留着） | 通过 | −0.033 米 |
| 模拟 6 分钟白天后 | 通过 | −0.033 米 |
| 模拟 30 分钟混合天气后（雨、风 1 沙尘、夜、雪、冰雹） | 通过 | −0.033 米 |
| 开镜头控制、风 1、`a.tries` 3、喝到一半被停掉 | 通过 | −0.033 米 |
| 最后开着镜头控制 | 通过 | −0.033 米 |
| 跑完整套 CI 沙漠检查后 3 次（会话约 4 小时模拟时间） | 3/3 通过 | −0.033 米 |

共 11 次，11 次通过，结果完全一样（嘴伸进水面以下 3.3 厘米，水平位置在水面范围内）。特写：`drink_closeup.png`。

## 附：数据来源说明

- 雨、黄昏、夜里的静帧数字来自同一流程的一次不录短片的重跑（同样的模拟时刻和机位）。对比图和短片来自完整的那次运行，两次静帧因为有按真实时间走的动画，会差几级亮度。短片平均是在对比短片的 36 帧上、用同一组采样点算的（`report_*_weather.json` 里的 `clipLuma`）。
- 本分支螃蟹 6 分钟统计来自完整的 shore 运行（它的 JSON 被暂存脚本改名时覆盖了，保留了运行打印的原始一行）。单只螃蟹特写和鱼影数字来自这两部分的重跑，对比图里本分支的螃蟹和鱼也用这次重跑的。完整运行里那只螃蟹在 6 分钟统计后自己走回水里（「去水里」模式，按设计不做让开），所以特写改用重跑。
